# 爆款视频拆解

把视频变成“可审计证据 → 结构化字段 → 可复用机制 → 飞书记录”，不要只给主观点评。

## 开始前

1. 完整读取 [references/field-schema.md](references/field-schema.md)，严格使用其中 22 个字段及顺序。
2. 完整读取 [references/quality-rubric.md](references/quality-rubric.md)，执行硬门槛与评分。
3. 需要设计产品/API/节点流程时，再读取 [references/automation-pipeline.md](references/automation-pipeline.md)。
4. 用户要求可复制 Prompt 时，读取并交付 [references/prompt-template.md](references/prompt-template.md)。

## 输入合同

优先收集：视频文件或可访问链接、渠道、素材 CID、投放目标、指标及归因窗口、同渠道/同人群基准、产品事实与能力边界、标签词表。缺失项用空字符串或 `待补充`，不得暗中补全。

只有同时具备“指标＋归因窗口＋基准”时，才能把素材判为付费/次留高低。否则 `渠道分类` 写 `待观察`，并在 `拆解证据` 写清缺失项。

## 拆解流程

### 1. 建立证据时间轴

- 读取时长、尺寸、帧率、音轨等媒体信息。
- 提取带时间码的 ASR 口播、OCR 字幕/UI 文案、镜头边界、关键帧、人物/产品/UI 状态、音乐节拍和音效。
- 先按画面显著变化切镜，再按语义动作合并；不要把鼠标移动或轻微动画误判成新镜头。
- 为每个结论保留至少一处时间码。将 `事实`、`推断`、`待核验` 分开记录。

### 2. 双层拆解

- 内容层：钩子 → 人群/痛点 → 承诺 → 功能/证据 → 结果 → CTA。
- 视听层：每个镜头的画面组成、景别、主体、动作、UI/字幕、声音、叙事作用；再单独记录镜头间如何转化，以及转换后的内容。

`分镜分析` 必须从 00:00 覆盖到片尾。`分镜转化分析` 只写镜头之间的关系；单镜头内的推拉摇移写在 `分镜分析`，不要混为转场。

### 3. 目标条件化判断

- 点击目标：更重视首屏停留、信息缺口和人群相关性。
- 付费目标：更重视价值证据、价格/权益、风险消除和唯一 CTA。
- 留存目标：更重视长期真实场景、持续价值、成功/失败边界。
- 双高目标：钩子、证据、真实使用链和 CTA 必须同时成立。

爆款与 Badcase 使用同一字段结构。Badcase 不单独造一套词汇：在字段内记录失效点，在 `拆解证据` 中写明 `失败机制`、时间码和反事实修法。

### 4. 抽象可复用公式

每个结论都按以下结构表达：

`观察事实 → 注意/理解/信任/行动机制 → 可迁移变量 → 适用条件 → 失效条件`

只迁移机制，不照搬专有文案、人物、品牌数据或偶然热点。没有画面证据的能力、数字、稀缺性和背书一律标 `待核验`。

### 5. 质检与输出

- 先执行 [references/quality-rubric.md](references/quality-rubric.md) 的硬门槛；硬门槛失败则标 `需人工复核`。
- 默认输出 UTF-8 JSON 数组；每个视频对应一个对象；键名与顺序完全匹配 22 个飞书列头。
- 每个单元格优先输出可读长文本，不在一个字段里塞未经定义的嵌套 JSON。
- 用户要求表格时，可额外给 Markdown 表；但机器写入以 JSON 为准。

## 飞书多维表格回填

只有用户明确要求写入并提供目标 Base/数据表时才执行写入。

1. 先读取目标数据表字段，按稳定 `field_id` 与显示名核对；不得只凭记忆写字段。
2. 检查 22 个列头是否存在且字段类型兼容。缺字段先报告，不擅自改名或覆盖旧字段。
3. 以素材链接或 CID 做去重键；两者都缺失时生成任务级临时键并标 `待上线回填`。
4. 批量写入前先预览 1 条；写入后抽查回读，确认长文本、换行和时间码未被截断。
5. 追加/更新遵从用户授权；不要删除用户记录。

## 输出顺序

1. `input_status`：已提供、缺失、采用的基准。
2. `quality_result`：硬门槛、总分、是否需复核。
3. `records`：严格 22 字段的 JSON 数组。
4. `method_card`：3–7 条可复用机制和对应失效条件。
