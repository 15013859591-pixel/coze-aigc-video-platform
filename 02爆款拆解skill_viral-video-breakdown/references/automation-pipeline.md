# 自动化闭环参考架构

## 推荐数据流

`用户目标/约束 → 素材接入 → 媒体预处理 → 多模态证据抽取 → 22字段拆解 → 质检/评分 → 飞书知识库 → 检索/公式选择 → 新脚本 → UI素材抓取/生成 → 自动剪辑 → 投放 → 指标回流`

## 节点与产物

1. **任务入口**：产品 UI 收集目标（点击/付费/留存/双高）、卖点、场景、人群、渠道、时长、比例、产品边界与禁用项，生成 `job_id`。
2. **素材接入**：保存原视频、来源 URL、CID、版本、哈希；同源剪辑版用 `creative_family_id` 关联，不覆盖。
3. **媒体预处理**：统一编解码；输出时长、分辨率、帧率、音轨；失败直接进入人工队列。
4. **多模态抽取**：ASR、OCR、镜头边界、关键帧、人物/产品/UI 区域、音乐节拍、音效；统一写成带时间码的 evidence events。
5. **UI 状态链**：从屏录识别 `页面 → 控件 → 点击/输入 → 加载/反馈 → 结果`；界面版本、语言或登录态不同必须标 `待核验`。
6. **拆解智能体**：只读取任务输入、产品事实和 evidence events，输出 22 字段 JSON；不直接写库。
7. **质检智能体/规则器**：验证键名、时间连续性、转场覆盖、禁用词、数字来源、标签词表、去重键和评分；失败进入人工复核。
8. **飞书写入器**：先查字段 schema，再按 `field_id` 批量 upsert；写后回读抽查。提示词、代码、版本和阈值放版本库，业务记录与审核状态放飞书，不把 Prompt 当数据行反复复制。
9. **脚本生成器**：按用户目标检索同渠道/同人群的好案例、相邻探索案例和 Badcase，选择 2–4 种不同机制，生成多候选并评分。
10. **UI 素材与剪辑**：脚本中的每个 UI 证据镜头转成机器可执行 shot spec；优先真实沙盒屏录，无法稳定操作时用版本化 UI 资产；按时间轴自动拼接、字幕、配音、音乐和转场。
11. **数据回流**：回填曝光、3 秒留存、CTR、CVR、付费率、次留、成本、样本量、归因窗口；只在样本量足够后更新好/坏标签与公式胜率。

## 存储职责

- **飞书多维表格**：素材元数据、22 字段拆解、审核状态、指标、公式标签、版本关系，供运营检索和人工校验。
- **对象存储**：原视频、音频、关键帧、UI 录屏、成片；飞书只存链接和索引。
- **关系数据库/任务队列**：用户、任务状态、节点重试、权限、计费、并发和幂等。
- **Git/版本库**：Prompt、Skill、标签词表、评分规则、镜头模板和工作流配置；所有线上任务记录版本号。
- **模型/工作流节点**：承载执行逻辑；不把 Prompt 硬编码在前端，也不靠人工逐次粘贴。

## 关键版本字段

每次拆解至少记录：`job_id`、`asset_hash`、`creative_family_id`、`prompt_version`、`skill_version`、`model_version`、`label_taxonomy_version`、`product_truth_version`、`review_status`、`created_at`。

## UI 自动抓取与自动剪辑原则

- 先把脚本变为 shot spec：镜头时长、页面、控件、动作、预期反馈、裁切区域、字幕、口播、转场和失败回退。
- 对真实产品使用受控沙盒账号＋固定测试数据＋浏览器/设备自动化录屏，避免抓到隐私和不稳定线上数据。
- 每一步都校验 UI 状态；找不到控件、超时、结果不一致时停止该镜头并回退到预置素材，不要继续错录。
- 剪辑器只消费通过校验的镜头；用镜头作用和节拍决定切点。UI 关键反馈优先硬切/动作衔接，反差或时间跳跃才使用更强转场。
- 生成后做 OCR 可读性、黑帧/静帧、字幕越界、音量、时长、关键卖点出现和 CTA 完整性检测。
